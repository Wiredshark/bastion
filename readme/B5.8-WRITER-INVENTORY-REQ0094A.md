## Classification vocabulary

Every reviewed path is assigned one of the requested classifications:

- **included traversal conflict** — can affect a colonist or its owned link;
- **source-proven component-impossible** — a required component/role excludes a
  colonist under a cited invariant (none of the uncertain paths below is placed
  here);
- **event-only/backstop** — only runs after an explicit event, command, fixture,
  or safety condition, but still interrupts an arbitrary target;
- **player/projectile-only** — handler eligibility is source-bound to a client,
  Presence, or projectile role and is not an ordinary colonist writer;
- **unresolved** — current source does not prove that a colonist can never carry
  the component. Stage 1 must guard it until research proves otherwise.

### Direct RTSim activity assignment scan

The machine guard scans every Rust file under `server/src` for the exact direct
assignment `rtsim_controller.activity =`. The complete current source set is:

1. `bastion-server/src/bastion_jobs.rs` — Bastion route lifecycle;
2. `server/src/rtsim/tick.rs` — loaded RTSim NPC state;
3. `server/src/lib.rs` — `bastion_goto_clear` harness hook.

The action queue finding is intentionally separate: guarding only the activity
assignment is insufficient because RTSim continues to extend actions and Agent
behavior consumes them.

`ConstructedLadderTraversal` remains subordinate provenance/energy data.

## Machine-checkable guard

`bastion-server/src/bastion_traversal_tooling.rs` tests:

- parse the structured table and bind each stable ID to its exact path, source
  marker, eligibility/phase, classification, policy, and falsifier;
- verify the bound source marker in each named writer/consumer path;
- recursively scan `server/src` and require the exact three direct RTSim
  activity-assignment owners above;
- deliberately remove `server/src/rtsim/tick.rs` from an in-memory document and
  require the guard to fail;
- build a synthetic token pile containing every required token but leave the
  Controller row incomplete, and require structured validation to fail.

The guard covers only the enumerated categories and markers above. It is
inventory drift detection, not a claim of a complete source scan or proof of
runtime exclusivity. A new writer or a different spelling still requires
research/source review.

## Unresolved Stage-1 guards

1. Interpolation attachment to server colonists is not disproven; guard the
   component until registration/attachment is source-proven impossible.
2. Tether leader/follower and mount/link composition require explicit policy;
   commands accept arbitrary UIDs.
3. RTSim actions must be paused/deferred or classified as atomic interruption,
   not merely hidden by an activity guard.
4. Interaction and arbitrary CharacterState resets can preempt Climb and must
   atomically abort/release traversal.
5. Terrain/teleport/mount-link/direct fixture relocation must invalidate the
   descriptor and reservation before position changes are accepted.
6. No current Specs declaration proves exclusive Agent/Bastion traversal
   ownership. The circuit breaker therefore remains triggered.
