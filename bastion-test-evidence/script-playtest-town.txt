note THREE-MODE PLAYTEST -- modes 1+2, ADOPTED VILLAGE deep dive.
note Sibling of script-playtest-arena.txt, same rhythm, DIFFERENT question.
note The arena asks "is the colony alive?" on ground the colony built itself.
note This asks the harder one: given a village it did NOT build, does the
note colony USE it -- sleep in the houses' beds, work the existing fields,
note walk the existing streets -- or does it ignore the town and re-found its
note own habits beside it? A colony camped in a field next to eleven empty
note beds is the specific failure this leg exists to catch.
note
note Run on the adoption arms (BASTION_ADOPT_TOWN=1 + real-terrain autofound +
note presence VD=3). Real terrain, so NO absolute coordinates appear below:
note the server picks the site, and a script that hard-coded a plot would be
note measuring its own guess. Everything here is relative to where the player
note anchors, which is the same rule script-adopt.txt follows.
note
note DECLARED RUN LENGTH (declare-run-length-before-launch):
note   3,000 settle + 8 x 2,000 cycle = 19,000 ticks
note   = ~633 game-seconds = ~10.5 game-minutes. Wall time is NOT declared
note   here. The settle is 3,000 and not 600 on purpose: the first adoption
note   leg with deferred placement drained all 5 designations one second
note   after founding and ended 44 wall-seconds later with ZERO arrivals --
note   an outcome its own window caused, because real-terrain pathing plus
note   eat cycles need thousands of ticks. EXPECT the same shape here; a
note   short window would score ordinary travel as failure.
note
note VOID CONDITIONS, named BEFORE the run:
note   V1 unloaded cells render `?` and never as ground. If the radius-60
note      frames stay mostly `?`, the presence radius is too small for a town
note      (the VD=3 lesson: adopted plot corners sat 48 blocks from origin
note      with min_loaded=false for an entire leg). Every "they ignore the
note      village" reading is then VOID -- the village was never loaded.
note   V2 if `count_items` shows zero materials throughout, the materials gate
note      refuses every claim (12,152/12,152 in the adoptfed forensics) and
note      "do they use the village" cannot be asked at all. Report VOID and
note      name the gate; do NOT report that the colonists ignored the town.
note   V3 ROOF OCCLUSION, the instrument limit that decides bar 2: a colonist
note      indoors may be UNDER a roof block and therefore invisible to a
note      surface renderer. If indoor colonists vanish from the frames, mode 2
note      CANNOT answer the bed question and it falls to `inspect_colonists`
note      alone -- absence of a glyph is then absence of EVIDENCE, not
note      evidence of absence, and the report must say which one it has.
note

note --- FRAME 1 (t=3000, 100 game-seconds) -- THE VILLAGE LAYOUT -----------
note Q: does the village read as ARCHITECTURE -- house footprints as enclosed
note   rectangles with a door gap, fields as regular blocks, paths between
note   them -- or as noise? A reader who cannot find a single house on this
note   frame cannot score any structure-use question that follows, and should
note   stop here and report the renderer, not the colony.
note Q: did adoption place the colony INSIDE the village footprint or on its
note   edge? EXPECT inside or adjacent. A colony centred well outside the
note   houses predicts every later "they ignore the village" answer for a
note   trivial reason -- distance -- and that must be stated up front rather
note   than discovered at cycle 8.
note Q: does `list_designations` show designations placed ON existing village
note   structures (beds where houses are, farm plots where fields are), or on
note   bare ground beside them? This is the adoption mechanism's own claim,
note   and it is checkable in one frame.
